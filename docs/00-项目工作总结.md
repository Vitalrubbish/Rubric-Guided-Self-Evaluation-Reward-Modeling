# Rubric-Guided Self-Evaluation and Reward Modeling — 项目工作总结

日期：2026-07-04
基座模型：Qwen2.5-7B-Instruct
主线 Benchmark：MBPP + HumanEval+ (coding, 1128 题)
补充 Benchmark：GSM8K (数学, n=100)、MATH safe-subset (迁移, n=100)、MATH full-format (压力测试, n=100)

---

## 一、项目目标

本项目探索一种 **不依赖人工标注评分标准** 的模型自我进化方案。核心思路是：

1. 让模型在 coding benchmark 上产生大量回答，用外部 verifier（单元测试）标记通过/失败
2. 从失败样本中自动发现错误模式，聚类生成 error taxonomy
3. 基于错误模式自动生成评分标准（rubric），覆盖多个评价维度
4. 用 rubric 作为 reward signal，通过 DPO 训练让模型自我改进
5. 探索三种方法变体：rubric-guided DPO（Method 1）、自我对弈错误发现（Method 2）、跨任务迁移（Method 3）

## 四、Phase 2：Rubric 自动生成与评估

### 4.1 Coding Rubric

基于 refined taxonomy 自动生成 **6 个评分维度**：

1. Functional Correctness and Edge-Case Coverage（功能正确性与边界覆盖）
2. Syntax Validity and Parseability（语法有效性与可解析性）
3. Interface and Test Contract Compliance（接口与测试契约合规）
4. Runtime Dependency and API Safety（运行时依赖与 API 安全）
5. Termination and Complexity Control（终止性与复杂度控制）
6. Output Cleanliness and Single-Solution Formatting（输出整洁度与单方案格式）

### 4.2 Rubric 区分度评估

| Rubric 类型 | Coverage | AUC | Kappa | Accuracy |
|-------------|----------|-----|-------|----------|
| Fixed/Generic rubric | 0.000 | 0.660 | 0.316 | 0.655 |
| Updated/Refined rubric | 1.000 | **0.801** | **0.525** | **0.765** |

结论：自动生成的 refined rubric 对通过/失败样本有较强区分度（AUC +0.142），可作为 reward/revision signal。

### 4.3 GSM8K Rubric

| 指标 | 数值 |
|------|------|
| 失败模式覆盖率 | 1.000 |
| Static AUC | 0.849 |
| Cohen's Kappa@4 | 0.051 |

GSM8K rubric 能排序区分好坏答案（AUC 高），但阈值化 self-evaluation 仍不稳定（Kappa 低），尤其会高估"推理格式完整但最终数字错误"的样本。

## 五、Method 1：Rubric-Guided DPO 训练

### 5.1 实验设计

Method 1 核心理念：错误模式 → 评分标准 → DPO reward → 模型自我改进。

本项目采用 **proxy A/B** 比较（fixed generic rubric vs. updated refined rubric），未跑完整在线双轨 RL。

### 5.2 多轮 DPO 实验

| 实验 | 偏好对数量 | 偏好准确率 | Raw Validation | Protected Validation | 说明 |
|------|-----------|-----------|----------------|---------------------|------|
| Full-failure DPO | 551 | 89.80% | 55/90 | — | 含 validation 泄漏，仅 sanity check |
| Train-only DPO | 158 | 69.60% | 33/90 | 50/90 | 无泄漏，单 DPO 无提升 |
| Augmented DPO | 212 | 76.90% | 37/90 | 54/90 | +54 条规则修正成功样本 |
| LLMCritic54 DPO | 266 | 79.70% | 43/90 | 54/90 | +54 条 LLM critic self-play 对 |
| LLMCritic54 + logic k=5 DPO | 273 | 80.59% | 42/90 | **56/90** | +7 条 logic self-play 对，最佳无泄漏 DPO |

### 5.3 Protected Rule Revision（保护版规则修正）

核心策略：只修改 verifier 判失败的样本，已通过样本完全不动。

| 方法 | 通过数 | 总数 | pass@1 | pass→fail |
|------|--------|------|--------|-----------|
| 原始 Qwen vLLM | 577 | 1128 | 51.15% | — |
| Unprotected revision | 745 | 1128 | 66.05% | 10 |
| **Protected revision** | **755** | **1128** | **66.93%** | **0** |

按数据集拆分：

| 数据集 | 通过数 | 总数 | pass@1 |
|--------|--------|------|--------|
| MBPP train | 270 | 374 | 72.19% |
| MBPP validation | 61 | 90 | 67.78% |
| MBPP test | 320 | 500 | 64.00% |
| HumanEval+ test | 104 | 164 | 63.41% |

### 5.4 Method 1 结论

- Updated rubric 明显提升 reward signal 区分度（AUC 0.660 → 0.801）
- DPO 训练闭环已完成，但效果弱于 protected deterministic revision（56/90 vs 61/90）
- Protected revision 无 reward hacking（pass→fail = 0），是当前最强 baseline
- 小规模 LoRA DPO 尚未完全吸收规则化修复能力

## 六、Method 2：Self-Play Error Discovery

### 6.1 实验设计

Method 2 核心理念：模型显式找错 → 生成改进版 B → 形成 A<B preference pair → DPO 训练。

与标准 self-rewarding 的区别：必须先显式定位错误、给出 critique，再写改进版。

### 6.2 LLM Critic 各变体结果

#### Syntax/Format 类错误（54 样本）

| 方法 | 尝试数 | 修复数 | 修复率 |
|------|--------|--------|--------|
| LLM Critic n=16 | 16 | 16 | 100% |
| **LLM Critic n=54** | **54** | **54** | **100%** |

Syntax/format 类错误修复稳定，模型能可靠地找到并修正格式问题。

#### Logic 类错误（20 样本，同一批）

| 方法 | 修复数 | 修复率 | Syntax Error |
|------|--------|--------|-------------|
| Default prompt, single candidate | 2/20 | 10% | — |
| Default prompt, k=3 | 6/20 | 30% | — |
| **Default prompt, k=5** | **7/20** | **35%** | — |
| Spec-first prompt v1 | 1/20 | 5% | 3 |
| Two-stage spec-code v1 | 3/20 | 15% | 0 |
| Algorithm-sketch v1 | 2/20 | 10% | 0 |

逻辑错误远比 syntax/format 困难。关键发现：

- **多候选 + verifier 筛选**有效：k=3 从 2/20 提升到 6/20
- **边际收益递减**：k=5 仅比 k=3 多修 1 题（7/20 vs 6/20）
- **Spec-first prompt 退化**：长 JSON 输出导致代码格式退化，引入 syntax error
- **Two-stage 消除格式问题**：拆开 spec 和 code 生成后 syntax error = 0
- **失败诊断**：17/17 失败分类为 `right_spec_wrong_algorithm`（规格正确但算法实现错误）
- **Algorithm sketch 无增益**：增加算法草图步骤未提升修复率

### 6.3 Verifier-Grounded Proxy Pairs

此外从 protected rule revision 构建了 178 条 proxy A<B 对（不是真实 LLM self-critique，但提供了 self-play 格式的数据基线）：

- 错误检测覆盖率：55.35%（失败样本中）
- 修复精度：58.36%（给定 edit 后的修复成功率）

### 6.4 Method 2 结论

- Syntax/format 类错误模型能可靠自发现和自修复（54/54）
- Logic 类错误需要更强信号，当前最佳 k=5 修复率仅 35%（7/20）
- 最终 DPO 结果：273-pair，raw validation 42/90，protected 56/90
- 对 7B 模型来说，单纯增加解释/草图步骤不能转化为更强修复能力

## 七、Method 3：Meta-Transfer（跨任务迁移）

### 7.1 Coding 侧：MBPP → HumanEval+

检查 coding refined rubric 能否从 MBPP 泛化到 HumanEval+：

| 数据子集 | N | Auto Rubric AUC | Generic Rubric AUC |
|----------|---|-----------------|-------------------|
| MBPP train | 374 | 0.798 | 0.653 |
| MBPP validation | 90 | 0.795 | 0.688 |
| MBPP test | 500 | 0.785 | 0.621 |
| HumanEval+ test | 164 | **0.846** | 0.824 |

Refined rubric 在未见过的 HumanEval+ 上仍有强区分度（AUC 0.846），提供了最小跨基准迁移证据。

### 7.2 数学侧：GSM8K → MATH Safe-Subset

MATH safe subset：Algebra + Prealgebra, Level 1-3, n=100。

| 指标 | 数值 |
|------|------|
| Qwen2.5-7B 准确率 | 83/100 = 83.00% |
| GSM8K-derived rubric zero-shot AUC | **0.883** |
| GSM8K-derived rubric Kappa@4 | 0.181 |
| MATH-derived rubric Kappa@4 | **0.596** |

GSM8K-derived rubric 在 MATH 上有 zero-shot ranking signal（AUC 0.883），但阈值化判断弱；MATH-derived rubric Kappa 更高，说明目标域失败模式对 rubric 校准有帮助。

### 7.3 Full MATH Verifier Pressure Test

扩展 verifier 支持集合、区间、根式、π、多答案、LaTeX 等价、千位逗号，在 all subjects Level 1-5 n=100 上测试：

| 指标 | 数值 |
|------|------|
| Gold verifier 自检 | 100/100 |
| Qwen2.5-7B 准确率 | 43/100 = 43.00% |
| GSM8K-derived rubric zero-shot AUC | 0.873 |
| GSM8K-derived rubric Kappa@4 | 0.123 |

按难度拆分：

| Level | 通过 | 总数 | 准确率 |
|-------|------|------|--------|
| Level 1 | 18 | 21 | 85.71% |
| Level 2 | 11 | 21 | 52.38% |
| Level 3 | 7 | 21 | 33.33% |
| Level 4 | 4 | 21 | 19.05% |
| Level 5 | 3 | 16 | 18.75% |

主要失败原因：`ambiguous_final_answer`（38/57），full MATH 的符号推理和 final-answer 格式更难。

### 7.4 Method 3 结论

- 跨代码任务迁移证据充分（MBPP → HumanEval+ AUC 0.846）
- GSM8K → MATH safe-subset zero-shot 迁移完成（AUC 0.883）
- Full MATH pressure test 是增强实验，不是完整 MATH test split meta-learning

## 九、需要诚实说明的 Caveats

1. **主 benchmark 是 coding**：GSM8K n=100 和 MATH 子集是补充附录，不是主训练 benchmark
2. **Method 1 是 proxy A/B**：fixed-vs-updated rubric 是离线对比，不是完整在线双轨 RL
3. **Method 3 是最小迁移**：包含 MBPP→HumanEval+ 和 GSM8K→MATH safe-subset，但不等于完整 MATH meta-learning
4. **DPO 弱于规则修正**：DPO 闭环完成，但 protected 后（56/90）仍弱于 protected rule revision（61/90）
5. **Random rubric ablation**：当前是 static scorer 接口，不是真 LLM 读取随机 rubric 后评分
6. **GSM8K self-eval Kappa 低**：ranking signal 存在（AUC 0.849）但阈值化 pass/fail 判断不稳定（Kappa 0.051）
